SignBridge

ASL recognition & learning platform

SignBridge makes American Sign Language easier to learn and use. It has three parts: one that reads signs from your webcam, one that turns typed English into sign videos, and one that teaches the alphabet like a game.

Try the live demoView code on GitHub

1. Recognize

You hold up a letter in front of your webcam. Google's MediaPipe finds 21 points on your hand, and a small neural network (an MLP classifier from scikit-learn) turns those points into a letter from A to Z. It reached about 86% accuracy on photos it had never seen.

2. Interpret

Type an English sentence and SignBridge plays real signer videos for words it knows. For any other word, it fingerspells the letters instead.

3. Learn

Lessons cover the full alphabet and common words, with XP, levels, streaks and quizzes. You can practice in front of the camera and the recognition model checks your sign.

How well the model works

Each row is the true letter and each column is the model's guess. A strong diagonal means most letters are read correctly.

Built with

React frontend, FastAPI backend, MediaPipe hand landmarks, scikit-learn MLP classifier.

Co-Wingman

Hybrid edge–cloud conversation assistant

Everyone loses their train of thought sometimes. Co-Wingman listens to a conversation on a small NVIDIA Jetson Orin Nano computer, notices an uncomfortable pause, and shows a short hint so the speaker can keep going.

How it works: speak, pause, recover

  1. On the device (edge): the Jetson turns speech into text, keeps a rolling summary of the conversation, and detects long pauses.
  2. In the cloud: when a pause is detected, a cloud AI model writes a short recovery cue based on what was just said.
  3. On screen: the cue appears so the speaker can pick up where they left off.

Running speech recognition on the device keeps it fast and private; only the short context goes to the cloud.

My part

I built the speaker-count module, which works out how many people are speaking in the conversation.

Results on the Jetson

110 msmedian speech-recognition time
1.04 smedian time to handle a cue
0 of 94audio windows dropped

Built with Mrunal Vibhute, Shrimayee Deshpande and Yasasvi Kaipa, and presented at HWCOE AI Days and UF AI Days 2026.

OrderFlow

Fault-tolerant e-commerce backend

When you buy something online, several things must happen: create the order, hold the stock, charge the card, and tell the customer. OrderFlow splits these into six small services that talk to each other through Kafka events, and it can undo work cleanly if any step fails.

View code on GitHub

The happy path

Order created→Stock reserved→Payment taken→Order confirmed→Customer notified

When something fails

Payment declined→Stock released→Order marked failed→Customer notified

What makes it reliable

  • Transactional outbox: a service saves its data and the event it must send in one database transaction, so an event is never lost.
  • Idempotent consumers: if the same event arrives twice, it is only processed once.
  • Retries and dead-letter queues: temporary errors are retried; events that keep failing are set aside for inspection.
  • No overselling: stock is reserved with optimistic locking, so two buyers can't take the last item.

Services

Auth, Product, Order, Inventory, Payment and Notification. Each has its own PostgreSQL database, with Redis caching for the product catalog and JWT login.

Testing

Unit and integration tests with JUnit and Testcontainers run in GitHub Actions, plus an end-to-end script that drives the full Docker Compose stack.

FeedForward

Research made scrollable · Education Track winner, UF GDG DevFest 2026

AI moves so fast that keeping up has become a task of its own. FeedForward makes AI research easy to discover and understand: you scroll a feed of research like social media, then dig into any paper with simple explanations, knowledge maps, flashcards and quizzes. Our motto: Discover. Understand. Remember.

View on DevpostView code on GitHub
1st placeEducation Track, UF GDG DevFest 2026
166research publishers in the source directory
4teammates, one day

What it does

  • Discover: a feed of curated AI research and verified publisher RSS updates, with "Latest" and "Timeless" views, search, topic filters and interest-based recommendations.
  • Understand: upload your own PDF or import an arXiv paper and get a beginner-friendly overview, key terms and source-backed notes, plus an AI chat that answers questions about the paper.
  • Remember: interactive knowledge maps show how ideas connect, and flashcards and quizzes help you revise. It can also prepare study material for NotebookLM.

How we built it

The frontend uses React, TypeScript, Vite and Tailwind CSS. The backend is Python with FastAPI. Uploaded PDFs are read with PyMuPDF, and explanations, knowledge maps, flashcards and quizzes are generated by Gemma models through UF's NaviGator AI API or Ollama. Knowledge maps are built with React Flow, and Firebase handles optional sign-in.

Keeping it accurate

We didn't want vague AI summaries that sound right but aren't. Explanations are grounded in the source text, keep track of citations, and are validated, with pytest tests on the backend.

Plant Detection

Medicinal plant identification with YOLOv8

Many people no longer recognize the medicinal plants around them. This app lets you upload a photo of a plant, finds the plant in the image, names it, and explains its traditional uses.

View code on GitHub

How it works

  1. You upload a photo in the Flask web app.
  2. A YOLOv8 object-detection model, trained on a public Roboflow dataset, draws a box around the plant and labels it.
  3. The app shows the species and its traditional medicinal uses.

It recognizes Neem, Oleander, Ficus Religiosa (peepal) and Calotropis.
